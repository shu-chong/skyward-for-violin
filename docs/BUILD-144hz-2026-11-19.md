## 为什么这次有机会

144 Hz 那次（2026-11-13）903 次 underflow 时，日志是 `last vote: ddr 0 MB/s, clk profile 1`：
DPU 不向 DVFS 投票，DDR 常驻最低档。现在 `dvfs::hold_memory_fast()` 把 `min_freq`
钉在 8.53 GHz，120 Hz 实测 0 underflow（含 23:12 之后约 2 分钟亮屏使用），
说明卡的是**调频延迟**而不是绝对带宽。144 Hz 只比 120 Hz 多 20% 像素率
（读 3.94 GB/s + 写回 3.94 GB/s ≈ 7.9 GB/s），同一个下限应当仍能覆盖。

## 上机验证清单

```sh
adb shell "grep -m1 'mode:' /sys/kernel/debug/dri/0/state"   # 期望 3200x2136x144
adb shell "cat /sys/class/devfreq/ddr_devfreq/min_freq"      # 期望 8533000000
adb shell "grep -ci underflow /tmp/kmsg.log"                 # 期望 0
adb shell "grep -ci 'keeps its own rate' /tmp/kmsg.log"      # 期望 0
```

画面撕裂 / 闪烁 / 局部错位 = underflow，直接回刷 120 Hz。

> 注：`/tmp/kmsg.log` 是上一版运行时挂的 `dmesg -w` 记录，**重启即丢失**。
> 144 版上机后需要重新挂：`adb shell "nohup setsid sh -c 'dmesg -w > /tmp/kmsg.log 2>&1' &"`。
